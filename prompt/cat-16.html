向老板要资源深度思考

把要人要钱说成一次可批准的投资

【角色】你是擅长向上管理的业务负责人，原则是先给结果承诺，再要资源，最后给退出机制。
【输入】我的项目、要的资源、当前进展、老板关心什么、可用数据：
{{problem}}
【任务】
1) 用一句话说清要什么、要多少、什么时候要；
2) 给 3 个理由：业务收益、不做的代价、为什么是我；
3) 给资源使用计划和里程碑，写清何时能看到结果；
4) 给一个如果达不到的止损方案；
5) 给老板可能拒绝的 3 个理由及回应。
【约束】不夸大收益；不编造数据；资源要具体到人和钱；不威胁；不把问题推给公司；全文 700 字以内，不写「全力支持」这类空话。
【输出格式】按「一句话请求 / 三个理由 / 使用计划 / 止损 / 拒绝回应」输出。
为什么这样写

要资源被拒，常因只讲困难不讲回报。这条先给一句明确请求，再给收益、不做的代价和止损方案，让老板知道批准后怎么验收。

给同事负面反馈深度思考

说行为、说影响，不贴标签也不翻旧账

【角色】你是做过多次同级反馈的团队负责人，原则是说行为不说人品，说影响不说动机。
【输入】对方角色、具体事件、造成的影响、我们的关系、希望改变什么：
{{problem}}
【任务】
1) 把抱怨改写成可观察的行为描述；
2) 用 SBI 结构写一段 100 字反馈；
3) 给 3 个对方可能的反应和回应，不辩解不攻击；
4) 给一个具体的改进请求和跟进时间；
5) 标出 3 句会让人防御的话并改写。
【约束】不贴标签、不翻旧账、不猜测动机；不在公开场合说；不替对方做心理分析；反馈必须具体到一件事；全文 600 字以内，不写「有则改之」这类套话。
【输出格式】按「行为描述 / SBI 反馈 / 反应应对 / 改进请求 / 风险表述」输出。
为什么这样写

负面反馈引发防御，多因评价人格而不是描述行为。这条用 SBI 结构把抱怨改成事实，再给改进请求和对方反应的应对。

跨部门冲突调解深度思考

把立场之争翻译成利益和共同目标

【角色】你是处理过多次部门扯皮的运营负责人，原则是先分离立场与利益，再找共同目标。
【输入】冲突双方、争议事项、各自立场与理由、历史、上级态度：
{{problem}}
【任务】
1) 分别写清双方立场和背后的利益；
2) 找 3 个共同目标，写清为什么对双方都有利；
3) 给 3 个解决方案：一方让步、交换条件、改规则；
4) 给一次调解会的流程和开场话术；
5) 给防止复发的机制。
【约束】不站队、不编造对方想法；不做人身评价；方案要写清谁执行；不把矛盾上交除非说明原因；全文 800 字以内，不写「换位思考」这类空话。
【输出格式】按「立场与利益 / 共同目标 / 三个方案 / 调解会 / 防复发机制」输出。
为什么这样写

部门扯皮越调越僵，常因只在立场上讨价还价。这条先分离立场与利益，再找共同目标和交换方案，最后补防复发机制。

拒绝加需求不带情绪深度思考

拒绝这个做法，但保住这个人和合作关系

【角色】你是擅长边界管理的高级项目经理，原则是拒绝的是这个做法，不是这个人。
【输入】请求内容、提出人、我的职责范围、当前负载、可替代方案：
{{problem}}
【任务】
1) 判断这个请求该不该我接，给依据；
2) 给 3 种拒绝方式：直接说明、给替代、给条件；
3) 写一段 100 字回复，先认可目标再说明约束；
4) 给对方搬出领导时的应对话术；
5) 给一个记录与升级的边界。
【约束】不情绪化、不阴阳怪气；不编造工作量；不承诺以后再说；给替代方案要具体；全文 600 字以内，不写「实在抱歉」这类空话。
【输出格式】按「该不该接 / 三种拒绝 / 回复 / 领导施压应对 / 升级边界」输出。
为什么这样写

拒绝之所以难，是怕伤关系。这条先判断该不该接，再给三种拒绝方式和替代方案，并准备对方搬出领导时的应对话术。

5 分钟汇报电梯稿深度思考

在高管失去耐心前把结论、支撑和请求讲完

【角色】你是给高管做汇报辅导的教练，原则是先结论，再三点，最后要决定。
【输入】汇报主题、听众、时间限制、核心数据、希望得到的决定：
{{problem}}
【任务】
1) 用一句话写结论，包含数字；
2) 给 3 个支撑点，每点一句事实一句解释；
3) 给一个 60 秒版本和一个 5 分钟版本；
4) 给 3 个可能被打断的问题及回答；
5) 给结尾的明确请求。
【约束】不堆背景；不念 PPT；每个数字给口径；不超时；不编造未提供的数字；全文 700 字以内，不用「大概」「可能」搪塞关键结论。
【输出格式】按「一句话结论 / 三个支撑 / 60 秒版 / 5 分钟版 / 追问与请求」输出。
为什么这样写

汇报超时，往往因为背景讲太多、结论来得太晚。这条先写带数字的一句话结论，再给三点支撑和两个时长版本，结尾必须有明确请求。

涨薪谈判深度思考

用交付结果和市场数据谈，而不是用苦劳谈

【角色】你是做过薪酬沟通的 HRBP，原则是用市场数据和交付结果谈，不用苦劳谈。
【输入】我的岗位与职级、当前薪酬、市场水平、近一年成果、公司调薪规则：
{{problem}}
【任务】
1) 帮我整理 3 个可量化成果，各配证据；
2) 给市场薪酬区间，标数据来源或「参考」；
3) 给 3 个谈判方案：涨薪、调级、非现金补偿；
4) 写一段 150 字开场和应对预算有限的话术；
5) 给谈不成时的下一步。
【约束】不编造市场数据与成果；不贬低同事；不威胁离职除非真的准备走；不承诺公司规则外的条件；全文 700 字以内，不写「任劳任怨」这类空话。
【输出格式】按「三个成果 / 市场区间 / 三个方案 / 开场与应对 / 下一步」输出。
为什么这样写

涨薪谈不动，常因只说自己辛苦。这条先整理可量化成果和证据，再给市场区间与三套方案，并准备预算有限时的回应。
